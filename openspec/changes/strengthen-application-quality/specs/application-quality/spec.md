## ADDED Requirements

### Requirement: Characterized application responsibilities
The system SHALL preserve observable application contracts during responsibility extraction.

#### Scenario: Asynchronous lifecycle
- **WHEN** audio, exercise, rendering or navigation is started, interrupted or disposed
- **THEN** ordering, visible errors and resource ownership match characterized behavior
- **AND** a reproduced defect is fixed with a regression scenario before refactoring

#### Scenario: Measured production functions
- **WHEN** application responsibilities are extracted
- **THEN** the original functions and every extracted helper remain measured
- **AND** explicit complexity and coverage protections are enforced by real tools

### Requirement: Verifiable application quality budgets
The system SHALL apply explicit quality budgets and selected static JavaScript contracts without disguising unmeasured sources.

#### Scenario: Budget regression
- **WHEN** measured production quality exceeds a versioned budget
- **THEN** validation reports the violated metric and fails
- **AND** fixtures exercise acceptance and rejection with the real implementation

#### Scenario: Selected JavaScript body checking
- **WHEN** selected JavaScript modules violate their static contracts
- **THEN** the actual compiler rejects them
- **AND** the selected scope is distinguished from declarations and the rest of the application

### Requirement: Cross-engine critical behavior evidence
The system SHALL exercise portable critical user interactions in Chromium, Firefox and WebKit.

#### Scenario: Built archive interactions
- **WHEN** critical interactions run against the verified public archive
- **THEN** navigation, input and preferences retain their observable contracts
- **AND** smoke coverage is not reported as exhaustive audio, graphics or accessibility certification

#### Scenario: Truthful delivery
- **WHEN** quality results or delivery are reported
- **THEN** source scopes, baseline, tested SHA and native artifacts are identified
- **AND** a successful pull request is distinguished from fusion, publication and archive authorization
