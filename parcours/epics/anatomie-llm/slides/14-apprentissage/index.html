Jusqu’ici, les poids étaient fixes. Ils ont pourtant été réglés un jour, par un processus très simple dans son principe : prédire, mesurer l’erreur, corriger un peu, et recommencer des millions de fois.

1 · AVANT DE MANIPULER

Comprendre le mécanisme.

L’exercice : deviner le token suivant

Le préentraînement transforme n’importe quel texte en exercices. Pour « le chat dort », l’entrée est « <bos> le chat dort » et les réponses attendues sont « le chat dort <eos> » : après <bos>, il faut prédire « le » ; après « le », « chat » ; et ainsi de suite. Grâce au masque causal, ces quatre exercices sont calculés en même temps, sans que chaque position puisse voir sa réponse.

La boucle d’apprentissage

  1. Prédire : le modèle calcule ses probabilités pour chaque position.
  2. Mesurer : la perte est faible si le bon token avait une forte probabilité, élevée sinon.
  3. Attribuer : la rétropropagation calcule, pour chaque poids, dans quel sens il faudrait le bouger pour réduire la perte : c’est le gradient.
  4. Corriger : un optimiseur déplace chaque poids d’un petit pas dans ce sens.

Luciole a répété cette boucle 12 000 fois. Les grands modèles la répètent sur des milliers de milliards de tokens.

Apprendre ou mémoriser ?

Une perte basse sur les phrases d’entraînement peut signifier que le modèle les a simplement retenues. Pour mesurer la généralisation, on suit la perte sur des phrases jamais vues : la validation. Les deux courbes de l’expérience montrent cet écart.

Après le préentraînement

Un modèle préentraîné sait continuer un texte, pas encore tenir une conversation. Le post-entraînement lui apprend à suivre des instructions sur des exemples de dialogues, puis à préférer certaines réponses : retours humains et renforcement (InstructGPT), optimisation directe de préférences (DPO), ou récompenses vérifiables (DeepSeek-R1). Luciole n’a suivi aucune de ces étapes.

Pour les avertis · perte, optimiseur et biais d’exposition

La perte est l’entropie croisée moyenne en nats/token : −ln(pcible). Une cible prédite à 50 % coûte environ 0,693 nat. La descente de gradient simple fait poids ← poids − taux × gradient ; Luciole utilise Adam, qui adapte ce pas avec des moyennes des gradients et de leurs carrés. À l’entraînement, les préfixes viennent toujours du corpus ; à la génération, ils contiennent les choix du modèle, qui peut donc s’éloigner des situations rencontrées.

Dans le code de Luciole · Prédire, comparer à la cible, calculer les gradients

La séquence contient <bos> et <eos>. slice(0, -1) retire le dernier token pour former les entrées ; slice(1) retire le premier pour former les cibles. crossEntropy mesure l’erreur ; backward calcule les gradients. La suite du script applique Adam pour modifier les poids, avant publication du modèle.

  parameters.forEach(p => p.grad.fill(0));
  const prediction = forward(sequence.slice(0, -1), tensors, config);
  const loss = crossEntropy(prediction.logits, sequence.slice(1));
  loss.backward();

À RETENIR

Préentraînement, post-entraînement et inférence sont des processus distincts ; seul l’entraînement modifie les poids.

LES LIMITES

Luciole a uniquement appris la prédiction du token suivant, sans instruction tuning ni préférences. Le curseur relit des mesures enregistrées et ne modifie aucun poids.

Le vocabulaire de cette étape
poids
Nombres ajustés pendant l’entraînement et conservés pendant la génération. Ils déterminent les transformations du modèle.
perte
Nombre qui mesure l’erreur selon l’objectif d’entraînement. Plus bas signifie meilleur sur cet objectif et ces données, pas sur toutes les tâches.
nats
Unité d’information utilisant le logarithme naturel. Une perte en nats n’est pas un taux d’erreur en pourcentage.
gradient
Ensemble de dérivées indiquant comment la perte varie lorsqu’on modifie chacun des paramètres.
rétropropagation
Calcul des gradients par propagation de la dérivée de la perte à travers les opérations.
généralisation
Capacité à réussir au-delà des exemples utilisés pour ajuster les paramètres.
validation
Lot exclu des mises à jour des poids, utilisé pour suivre les résultats pendant l’entraînement. Il peut informer les choix de développement, contrairement au test final.
test
Lot réservé à la mesure finale. Ici, il contient des combinaisons synthétiques inédites, mais des mots et des patrons connus.

3 · VÉRIFIER SA COMPRÉHENSION

Une perte d’entraînement très basse prouve-t-elle une bonne généralisation ?

Lire la correction

Non, il faut évaluer sur des données mises de côté. Un modèle peut mémoriser ses exemples. Seule une évaluation sur des données distinctes renseigne sur sa généralisation.
