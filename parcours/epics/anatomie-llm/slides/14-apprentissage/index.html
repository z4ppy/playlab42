1 · AVANT DE MANIPULER

Comprendre le mécanisme.

Le préentraînement ajuste les poids pour mieux prédire des tokens sur un corpus. Une fonction de perte mesure l’erreur ; la rétropropagation calcule les gradients ; un optimiseur met à jour les paramètres.

Pour apprendre sur « le chat dort », les entrées sont « <bos> le chat dort » et les cibles « le chat dort <eos> ». Après <bos>, le modèle doit prédire « le » ; après « le », « chat » ; après « chat », « dort » ; après « dort », la fin. L’entrée et les cibles sont donc décalées d’un token. Le masque causal empêche chaque position de consulter les suivantes, même lorsque plusieurs prédictions sont calculées en parallèle.

À l’entraînement, les préfixes viennent ici du texte du corpus. Pendant la génération, ils incluent les tokens choisis par le modèle : une erreur peut donc modifier les prédictions suivantes. La perte récompense la probabilité donnée à la cible du corpus ; elle ne teste pas directement la vérité de toute phrase produite.

Le post-entraînement peut apprendre à suivre des instructions, utiliser des préférences entre réponses ou des récompenses vérifiables. InstructGPT décrit un exemple avec retours humains et apprentissage par renforcement ; DPO optimise directement un objectif à partir de paires préférées/rejetées. Ce sont des recettes distinctes, pas des étapes obligatoires que tous les modèles suivraient.

Les courbes proviennent du préentraînement réel de Luciole : 12 000 mises à jour, 1 512 phrases d’apprentissage, graine 42. Elles suivent des exemples fixes d’apprentissage et de validation. Le curseur permet de relire des prédictions enregistrées ; il ne modifie aucun poids. La fiche Luciole expose aussi le test final, réservé jusqu’à la fin de ce calcul.

Une baisse de perte signifie moins d’erreur sur l’objectif mesuré, pas une compétence universelle. Les phrases Tatoeba enrichissent les langues rencontrées ; les tests synthétiques vérifient seulement certaines recombinaisons. Les échecs sur les boîtes restent visibles.

Facultatif · une mise à jour simplifiée

poids ← poids − taux_apprentissage × gradient. Ce schéma décrit une descente de gradient simple ; Luciole a été entraîné avec Adam, qui utilise aussi des moyennes des gradients et de leurs carrés. Aucun de ces ajustements ne s’exécute quand vous déplacez le curseur.

Dans le code de Luciole · Prédire, comparer à la cible, calculer les gradients

La séquence contient <bos> et <eos>. slice(0, -1) retire le dernier token pour former les entrées ; slice(1) retire le premier pour former les cibles. crossEntropy mesure l’erreur ; backward calcule les gradients. La suite du script applique Adam pour modifier les poids, avant publication du modèle.

  parameters.forEach(p => p.grad.fill(0));
  const prediction = forward(sequence.slice(0, -1), tensors, config);
  const loss = crossEntropy(prediction.logits, sequence.slice(1));
  loss.backward();

À RETENIR

Préentraînement, post-entraînement et inférence sont des processus distincts.

LES LIMITES

Luciole a uniquement appris la prédiction du token suivant. Il n’a reçu ni instruction tuning ni entraînement par préférences.

Le vocabulaire de cette étape
poids
Nombres ajustés pendant l’entraînement et conservés pendant la génération. Ils déterminent les transformations du modèle.
perte
Nombre qui mesure l’erreur selon l’objectif d’entraînement. Plus bas signifie meilleur sur cet objectif et ces données, pas sur toutes les tâches.
nats
Unité d’information utilisant le logarithme naturel. Une perte en nats n’est pas un taux d’erreur en pourcentage.
gradient
Ensemble de dérivées indiquant comment la perte varie lorsqu’on modifie chacun des paramètres.
rétropropagation
Calcul des gradients par propagation de la dérivée de la perte à travers les opérations.
généralisation
Capacité à réussir au-delà des exemples utilisés pour ajuster les paramètres.
validation
Lot exclu des mises à jour des poids, utilisé pour suivre les résultats pendant l’entraînement. Il peut informer les choix de développement, contrairement au test final.
test
Lot réservé à la mesure finale. Ici, il contient des combinaisons synthétiques inédites, mais des mots et des patrons connus.

3 · VÉRIFIER SA COMPRÉHENSION

Une perte d’entraînement très basse prouve-t-elle une bonne généralisation ?

Lire la correction

Non, il faut évaluer sur des données et tâches distinctes. Un modèle peut mémoriser les exemples. Une évaluation indépendante est nécessaire pour étudier sa généralisation.
