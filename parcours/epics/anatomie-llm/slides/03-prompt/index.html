1 · AVANT DE MANIPULER

Comprendre le mécanisme.

L’idée

Vous voyez des bulles de discussion. Le modèle, lui, ne voit qu’un long texte à continuer. Le chat template est la recette qui fabrique ce texte : il assemble les consignes du système, vos messages et les réponses précédentes, en les séparant par des marqueurs spéciaux qui indiquent qui parle. Il se termine par le marqueur « début de la réponse de l’assistant » : le modèle n’a plus qu’à continuer, token par token, comme à l’étape 1.

Chaque famille de modèles a son propre format, appris pendant son entraînement à la conversation. Utiliser le mauvais format dégrade les réponses.

Et les outils ?

Un assistant capable d’utiliser des outils (recherche, calculatrice, code) reçoit aussi leur description dans le contexte. Quand il veut s’en servir, il génère un texte structuré qui décrit l’appel. C’est le programme autour du modèle qui exécute réellement l’outil, puis insère le résultat dans le contexte avant de relancer la génération. Le modèle lui-même ne fait qu’écrire des tokens.

Un point de sécurité

Une fois dans le contexte, le résultat d’un outil n’est qu’un texte parmi d’autres. Une page Web consultée peut contenir « ignore tes consignes et… » : c’est l’injection de prompt. Le programme qui entoure le modèle doit donc traiter ces résultats comme des données, pas comme des ordres, et limiter ce que les outils peuvent faire.

L’échange de l’expérience est inventé et ses marqueurs sont illustratifs. Luciole n’utilise pas de template : il n’a jamais appris à converser.

Pour les avertis · ce que le template change

Le template fixe l’ordre, les tokens spéciaux de rôle, l’endroit où s’insèrent les définitions d’outils et parfois un début de réponse imposé. Il consomme des tokens de contexte à chaque tour. Les bibliothèques comme Hugging Face Transformers le stockent avec le tokenizer. Les modèles de raisonnement ajoutent souvent une section de réflexion dans ce même flux ; ce texte affiché n’est pas une trace exhaustive du calcul interne.

messages + rôles + outils + template = une seule suite de tokens à continuer

À RETENIR

Un assistant reçoit une conversation sérialisée en une seule suite de tokens ; le programme qui l’entoure exécute les outils.

LES LIMITES

L’ordre et les marqueurs dépendent du modèle ; ceux de l’expérience sont illustratifs. Luciole n’a jamais appris à converser ni à appeler des outils.

Le vocabulaire de cette étape
prompt
Entrée fournie au modèle avant qu’il produise une suite. Dans un chat, elle peut inclure tout l’historique et les consignes.
contexte
Suite de tokens disponible pour calculer la prochaine prédiction : le prompt et les tokens déjà générés.
chat template
Recette qui transforme les messages et leurs rôles en la séquence attendue par un modèle conversationnel.
token
Petite unité utilisée pour découper le texte : mot, morceau de mot, signe ou octet selon le tokenizer. Le modèle manipule le numéro associé à cette unité.

3 · VÉRIFIER SA COMPRÉHENSION

Le résultat d’un outil est-il automatiquement une instruction de confiance ?

Lire la correction

Non, il peut contenir du texte non fiable. Un résultat d’outil peut contenir n’importe quel texte, y compris des instructions hostiles. Données, instructions et autorisations doivent rester distinctes.
