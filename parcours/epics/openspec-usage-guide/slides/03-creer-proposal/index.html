Étape 1 · Proposer

Créer une proposal

Une proposal bien faite répond à trois questions : pourquoi, quoi et comment le vérifier. Elle se relit avant d'écrire le moindre code.

Quand proposer ?

Oui

  • Nouvelle fonctionnalité ou nouveau jeu
  • Changement de comportement ou d'architecture
  • Modification d'un contrat (manifeste, spec existante)

Pas nécessaire

  • Correction de bug qui rétablit le comportement spécifié
  • Faute de frappe, formatage, commentaire
  • Mise à jour de dépendance sans impact fonctionnel

En cas de doute, lancez d'abord /opsx:explore pour clarifier.

Lancer la proposition

Choisissez un nom en kebab-case commençant par un verbe : add-dark-mode, fix-…, refactor-….

Chat de l'assistant 
/opsx:propose add-dark-mode

Cursor et GitHub Copilot (IDE) : /opsx-propose add-dark-mode.

Dans Playlab42

Les commandes slash OPSX ne sont pas générées (livraison skills-only) : demandez le skill par son nom. Playlab42 gère déjà les thèmes ; add-dark-mode reste un exemple illustratif. 

Utilise le skill openspec-propose pour préparer le changement add-dark-mode

Ce skill s'arrête aux artefacts de planification ; relisez-les, puis demandez explicitement openspec-apply-change. Détails : guide OpenSpec de Playlab42.

En profil étendu, vous pouvez aussi procéder pas à pas avec /opsx:new puis /opsx:continue ou /opsx:ff.

Ce que l'assistant produit

Exemple illustratif pour le fil rouge :

1. proposal.md — le pourquoi et le quoi

# Proposal: Add Dark Mode

## Intent
Réduire la fatigue visuelle lors d'une utilisation nocturne.

## Scope
- Ajouter un sélecteur de thème (clair / sombre)
- Détecter la préférence système
- Hors périmètre : thèmes personnalisés

## Approach
Variables CSS pour les couleurs, préférence conservée localement.

2. specs/ui/spec.md — le delta

# Delta for UI

## ADDED Requirements

### Requirement: Choix du thème
L'application MUST permettre de choisir entre un thème clair et un thème sombre.

#### Scenario: Bascule manuelle
- GIVEN un utilisateur sur n'importe quelle page
- WHEN il active le thème sombre
- THEN l'interface passe immédiatement en sombre

Les sections possibles sont ADDED, MODIFIED et REMOVED Requirements. Chaque exigence a au moins un scénario. Gardez les marqueurs Requirement:, Scenario: et le mot normatif MUST ou SHALL en anglais, même quand le reste du texte est en français : le validateur les reconnaît.

3. design.md et tasks.md

# Tasks

## 1. Thème
- [ ] 1.1 Définir la palette sombre en variables CSS
- [ ] 1.2 Ajouter le sélecteur de thème

## 2. Tests
- [ ] 2.1 Couvrir le scénario « Bascule manuelle »

design.md consigne les choix techniques ; il est utile dès qu'il y a un compromis à expliquer, facultatif pour un changement trivial.

Relire et valider

Dans Playlab42, le CLI local épinglé passe par Docker (jamais npm sur l'hôte) ; dans un projet générique, utilisez directement openspec list, show et validate. 

make openspec-list
make npm CMD="exec -- openspec show add-dark-mode"
make npm CMD="exec -- openspec validate add-dark-mode --strict --no-interactive"
make openspec-validate
  • L'intention et le périmètre sont clairs, y compris ce qui est exclu.
  • Chaque exigence a un scénario vérifiable.
  • Les tâches sont petites et ordonnées.
  • La validation du CLI passe, et l'équipe a relu avant apply.
