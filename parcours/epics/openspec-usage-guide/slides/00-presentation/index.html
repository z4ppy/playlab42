Parcours OpenSpec · version 1.14.0

OpenSpec — Spécifier avant de coder

OpenSpec aide l'équipe et l'assistant IA à se mettre d'accord sur ce qu'il faut construire avant la première ligne de code, puis à garder les specs à jour.

Ce que vous saurez faire

Comprendre

Le développement piloté par les specs, la source de vérité et les delta specs.

Installer

Node.js ≥ 20.19, openspec init, openspec update et les profils, dans un projet générique.

Piloter

Explorer, proposer, appliquer, archiver — sans cascade rigide.

Contribuer à Playlab42

Utiliser le CLI local épinglé et les skills déjà générés dans le dépôt.

Fil rouge du parcours

Un exemple illustratif revient dans chaque slide : le changement add-dark-mode, l'exemple de la documentation officielle (ajouter un mode sombre). Playlab42 gère déjà les thèmes : ce n'est pas un changement réel du dépôt, il sert à suivre un cycle complet.

  1. Explorer l'idée et le code existant.
  2. Proposer : proposal, delta specs, design, tasks.
  3. Appliquer les tâches en mettant à jour les artefacts si besoin.
  4. Archiver : les deltas rejoignent la source de vérité.

Parcours ≠ dépôt

Le parcours explique d'abord OpenSpec 1.14.0 de façon générique (installation globale, openspec init, commandes /opsx:*). Dans Playlab42, rien de cela n'est à refaire : le CLI est une dépendance de développement épinglée, exécutée dans Docker, et les skills openspec-* du profil core sont déjà générés (livraison skills-only). Voir le guide OpenSpec de Playlab42.

Sources officielles : Getting Started, Concepts (tag v1.14.0 ; docs main identiques à la vérification).
