Le workflow

Des actions, pas des phases

OpenSpec propose des actions que l'on enchaîne selon le besoin. Rien ne vous empêche de corriger la proposal pendant l'implémentation : ce n'est pas une cascade.

Chemin par défaut : profil core

  1. /opsx:explore optionnel — réfléchir avec l'IA, sans écrire de code.
  2. /opsx:propose — crée le changement et tous ses artefacts de planification.
  3. /opsx:apply — implémente les tâches de tasks.md.
  4. /opsx:sync optionnel — fusionne les deltas dans les specs principales sans archiver.
  5. /opsx:archive — archive le changement terminé.

En v1.14.0, le profil core compte six commandes (propose, explore, apply, update, sync, archive), et non quatre comme le suggèrent des résumés plus anciens.

/opsx:update ≠ openspec update

/opsx:update (chat) révise uniquement les artefacts de planification d'un changement ; il ne modifie pas le code (suivez-le d'un /opsx:apply). openspec update (terminal) est une commande du CLI qui régénère les fichiers d'intégration (skills, commandes) selon votre profil. 

/opsx:explore               # idée floue : on clarifie d'abord
/opsx:propose add-dark-mode
/opsx:apply
/opsx:archive

Ces lignes se tapent dans le chat de l'assistant. Cursor et GitHub Copilot (IDE) utilisent /opsx-propose, /opsx-apply, etc.

Workflow étendu (optionnel)

Les commandes suivantes ne sont pas installées par défaut. Pour les activer : 

openspec config profile   # sélectionner les workflows
openspec update           # régénérer les fichiers du projet (projet générique)
CommandeRôle
/opsx:newCrée le dossier du changement (scaffold)
/opsx:continueCrée l'artefact suivant selon les dépendances
/opsx:ffFast-forward : crée tous les artefacts d'un coup
/opsx:verifyVérifie que le code correspond aux artefacts
/opsx:bulk-archiveArchive plusieurs changements à la fois
/opsx:onboardTutoriel guidé du workflow complet

Chemin étendu typique : new → ff ou continue → apply → verify → archive.

Itérer sans waterfall

  • Les artefacts se construisent les uns sur les autres, mais on peut revenir à n'importe lequel.
  • Pendant apply, un défaut de conception ? Mettez à jour design.md ou les deltas, puis continuez.
  • Un changement déjà codé dont le plan a évolué : /opsx:update, puis /opsx:apply pour réaligner le code.
  • Plusieurs changements peuvent coexister, chacun dans son dossier.

Dans Playlab42 : skills, pas commandes slash

Le profil core y est déjà installé en livraison skills-only : demandez à l'assistant d'utiliser openspec-explore, openspec-propose, openspec-apply-change, openspec-update-change, openspec-sync-specs ou openspec-archive-change. Les commandes /opsx:* ne sont pas disponibles automatiquement ; lisez-les comme les noms des actions. Le workflow étendu n'est pas installé.

openspec config profile et openspec update décrits plus haut concernent un projet générique : ne les lancez pas directement dans le worktree (voir le guide OpenSpec de Playlab42).
