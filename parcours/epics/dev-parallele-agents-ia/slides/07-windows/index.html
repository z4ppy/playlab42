🪟 Spécificités Windows

💻 Windows Terminal remplace tmux

Windows Terminal gère nativement les panneaux et les onglets :

RaccourciAction
Alt+Shift++Nouveau panneau à droite
Alt+Shift+-Nouveau panneau en dessous
Alt+Shift+DDupliquer le panneau courant (sens automatique)
Alt + flèchesChanger de panneau
Ctrl+Shift+WFermer le panneau

Pour ouvrir directement trois panneaux depuis PowerShell, le ; destiné à wt doit être échappé par un accent grave :

wt -p "Windows PowerShell" `; split-pane -H `; split-pane -V

Remplacez "Windows PowerShell" par le nom exact de votre profil.

⚙️ Git sur Windows

# Fins de ligne : un choix d'équipe, à fixer aussi dans .gitattributes
git config --global core.autocrlf false

# Liens symboliques (désactivés par défaut dans Git for Windows)
git config --global core.symlinks true

# Chemins de plus de 260 caractères (quelques limites dans l'Explorateur et cmd.exe)
git config --system core.longpaths true

Créer des liens symboliques demande un privilège réservé par défaut aux administrateurs ; depuis Windows 10 version 1703, activer le mode développeur lève cette restriction.

🛡️ Antivirus et performances : préférer Dev Drive

L'analyse en temps réel de Microsoft Defender ralentit les opérations Git et Node sur des milliers de petits fichiers. Microsoft recommande un Dev Drive (Windows 11) pour les dépôts, caches de paquets et sorties de build : son « mode performance » est présenté comme une alternative plus sûre aux exclusions de dossiers.

Si vous gardez des exclusions, limitez-les à vos projets (PowerShell administrateur) :

Add-MpPreference -ExclusionPath "$env:USERPROFILE\Projects"

Évitez les exclusions par processus (node.exe, git.exe) : elles excluent tous les fichiers ouverts par ces programmes, où qu'ils soient.

🐧 WSL2 : une option solide

Règle importante : si vous travaillez dans le terminal Linux, gardez vos projets dans le système de fichiers Linux (/home/<utilisateur>/projets) et non sous /mnt/c/. Microsoft déconseille de travailler à cheval entre les deux systèmes de fichiers et recommande, pour de meilleures performances, de stocker les fichiers du côté de l'outil qui les utilise.

VS Code se connecte à WSL avec l'extension WSL ; les worktrees, tmux et les agents fonctionnent comme sous Linux.
