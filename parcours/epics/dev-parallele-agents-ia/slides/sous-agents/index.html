🧩 Paralléliser dans une session : les sous-agents

Jusqu'ici, vous lancez plusieurs agents et vous les coordonnez. Les agents récents savent aussi le faire eux-mêmes : une session principale délègue des sous-tâches à des sous-agents, attend leurs résultats et les intègre.

Les sous-agents de Claude Code

Chaque sous-agent a sa propre fenêtre de contexte, son prompt système, ses outils et ses permissions. La session principale ne reçoit que son résultat, ce qui la garde lisible. Des sous-agents en arrière-plan peuvent tourner en même temps pendant que vous continuez à travailler ; /tasks les liste.

On les définit dans .claude/agents/ (projet) ou ~/.claude/agents/ (personnel) :

---
name: redacteur-tests
description: Écrit des tests unitaires pour un module donné, sans modifier le code de production
tools: Read, Grep, Glob, Edit, Bash
isolation: worktree
---
Tu écris des tests Jest en français pour le module indiqué.
Tu ne modifies que les fichiers de test. Tu termines par la liste des tests ajoutés
et le résultat de leur exécution.

isolation: worktree fait travailler le sous-agent dans un worktree temporaire, supprimé automatiquement s'il n'a rien modifié. Attention : ce worktree part par défaut de la branche par défaut du dépôt, pas de votre HEAD ; un travail non poussé sur votre branche n'y figure pas. Sans cette option, les sous-agents écrivent dans les mêmes fichiers que la session principale : ne leur confiez alors que des zones disjointes.

Agent teams (expérimental)

Claude Code propose aussi des équipes : une session « chef » et des coéquipiers, chacun avec son contexte, qui partagent une liste de tâches et s'envoient des messages. La fonction est expérimentale et désactivée par défaut (variable CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1). Réservez-la à l'expérimentation.

Chez les autres outils

  • Copilot CLI : /fleet répartit des tâches indépendantes entre sous-agents. Voir le chapitre Fleet du parcours GitHub Copilot.
  • Cursor : /best-of-n lance la même tâche sur plusieurs modèles, chacun dans son worktree, pour comparer les résultats.

Avant de déléguer

  1. Ne parallélisez que des tâches indépendantes : un sous-agent qui attend une décision d'un autre ne gagne rien.
  2. Attribuez une zone de fichiers à chaque sous-agent, ou demandez l'isolation en worktree.
  3. Exigez une sortie vérifiable : fichiers touchés, commandes lancées et leur résultat, questions ouvertes.
  4. Relancez les validations transversales (tests, lint) après l'intégration, pas seulement dans chaque sous-agent.

Le coût. Chaque sous-agent relit du contexte et appelle des outils et des modèles. Le parallélisme réduit le temps d'attente mais augmente la consommation totale. Pour lire deux petits fichiers, un seul agent suffit.
