📎 Annexe A : script de démarrage

Crée un worktree et une fenêtre tmux par spec, puis lance Claude Code. Les specs doivent être commitées : c'est le commit, pas votre dossier de travail, que reçoivent les worktrees. 

#!/usr/bin/env bash
# start-agents.sh <projet> <spec1> [spec2] ...
# Exemple : start-agents.sh mon-projet auth-oauth api-notifications
set -euo pipefail

PROJECT="${1:?Usage: start-agents.sh <projet> <spec1> [spec2] ...}"
shift
if [[ $# -eq 0 ]]; then
  echo "Indiquez au moins une spec (fichier specs/<nom>.md commité)." >&2
  exit 1
fi

PROJECT_ROOT="$HOME/projets/$PROJECT"
WORKTREES_DIR="$PROJECT_ROOT-worktrees"
SESSION="agents-$PROJECT"

git -C "$PROJECT_ROOT" rev-parse --git-dir >/dev/null   # échoue si ce n'est pas un dépôt
if tmux has-session -t "$SESSION" 2>/dev/null; then
  echo "La session tmux $SESSION existe déjà : tmux attach -t $SESSION" >&2
  exit 1
fi

tmux new-session -d -s "$SESSION" -n suivi -c "$PROJECT_ROOT"
tmux send-keys -t "$SESSION:suivi" "watch -n 5 git worktree list" C-m

index=0
for spec in "$@"; do
  index=$((index + 1))
  # La spec doit exister dans le commit courant, sinon le worktree ne la contiendra pas
  if ! git -C "$PROJECT_ROOT" cat-file -e "HEAD:specs/$spec.md" 2>/dev/null; then
    echo "⚠️  specs/$spec.md absent du commit courant : ignoré" >&2
    continue
  fi

  branch="agent-$index-$spec"
  worktree="$WORKTREES_DIR/$branch"
  git -C "$PROJECT_ROOT" worktree add -b "$branch" "$worktree" HEAD

  # Les fichiers ignorés par Git (comme .env) ne sont pas copiés par worktree add
  if [[ -f "$PROJECT_ROOT/.env" ]]; then
    cp "$PROJECT_ROOT/.env" "$worktree/"
  fi

  tmux new-window -t "$SESSION" -n "agent-$index" -c "$worktree"
  tmux send-keys -t "$SESSION:agent-$index" "claude \"Implémente @specs/$spec.md\"" C-m
  echo "✅ Agent $index : specs/$spec.md dans $worktree"
done

tmux attach-session -t "$SESSION"

Pensez aussi à installer les dépendances dans chaque worktree (npm ci, etc.) et à décaler les ports dans chaque .env si vos tests lancent des services. Le .env doit être listé dans .gitignore : un fichier ignoré n'empêche pas git worktree remove, un fichier simplement non suivi, si.

📎 Annexe B : script de nettoyage

Supprime les worktrees propres et signale les autres, sans jamais forcer : un worktree « sale » contient du travail non commité.

#!/usr/bin/env bash
# cleanup-agents.sh <projet>
set -euo pipefail

PROJECT="${1:?Usage: cleanup-agents.sh <projet>}"
PROJECT_ROOT="$HOME/projets/$PROJECT"
WORKTREES_DIR="$PROJECT_ROOT-worktrees"

if [[ ! -d "$WORKTREES_DIR" ]]; then
  echo "Rien à nettoyer"
  exit 0
fi

shopt -s nullglob   # aucun tour de boucle si le dossier est vide
for worktree in "$WORKTREES_DIR"/*/; do
  worktree="${worktree%/}"
  if git -C "$PROJECT_ROOT" worktree remove "$worktree"; then
    echo "🧹 Supprimé : $worktree"
  else
    echo "⚠️  Conservé (modifications non commitées) : $worktree" >&2
  fi
done

git -C "$PROJECT_ROOT" worktree prune
rmdir "$WORKTREES_DIR" 2>/dev/null && echo "Dossier $WORKTREES_DIR supprimé"
echo "Branches restantes : git -C $PROJECT_ROOT branch --list 'agent-*'"

@AGENTS.md
