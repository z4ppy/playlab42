🚫 Les pièges à éviter

📋 Erreurs de découpage

❌ Piège✅ Parade
Des tâches qui touchent les mêmes fichiersRevoir le découpage : une zone de fichiers par agent.
Un périmètre vague dans la specLister explicitement les fichiers et dossiers autorisés, et ceux interdits.
Pas d'interface entre tâches dépendantesÉcrire et commiter types et contrats avant de lancer les agents.
Specs écrites mais pas commitéesCommiter sur la branche de base avant de créer les worktrees : sinon les agents ne les voient pas.

👀 Erreurs de supervision

❌ Piège✅ Parade
Micro-management en temps réelLancer, puis passer à intervalles réguliers. Les interruptions constantes cassent le travail de l'agent… et le vôtre.
Aucune supervisionUn passage toutes les 15 à 30 minutes évite qu'un agent tourne en rond pendant deux heures.
Croire le résumé de l'agentRelancer soi-même tests et lint. Un résumé peut annoncer des tests au vert qui n'ont pas tourné.
Fusionner sans relectureToujours relire, y compris la sécurité (voir les chiffres ci-dessous).

Ce que disent les études sur la sécurité du code généré

  • Sur 80 tâches de test conçues autour de failles connues, le code produit par plus de 100 modèles contient une vulnérabilité dans environ 45 % des cas (Veracode, 2025 GenAI Code Security Report, juillet 2025).
  • Sur 470 pull requests open source, celles co-écrites par IA contiennent environ 1,7 fois plus de problèmes que les PR humaines, et jusqu'à 2,74 fois plus de problèmes de sécurité (CodeRabbit, décembre 2025).

Ce sont des mesures sur des échantillons précis, pas une loi générale ; elles suffisent à justifier une relecture systématique.

⚙️ Erreurs techniques

❌ Piège✅ Parade
Plusieurs agents dans le même répertoireUn worktree par agent, sans exception.
Forcer une branche dans deux worktrees (--force)Une branche par agent ; créez-en une nouvelle plutôt que de contourner le garde-fou.
Utiliser git stash pour « mettre de côté » dans un worktreeLe stash est partagé par tous les worktrees : préférez un commit de travail sur la branche.
Oublier les dépendancesChaque worktree a ses propres node_modules et builds : installez-les avant de lancer l'agent.
Deux worktrees sur les mêmes portsParamétrer les ports par worktree (fichier .env), ou passer par des agents cloud.
Pas de stratégie d'intégrationDéfinir l'ordre des PR avant de lancer les agents.
Oublier le nettoyageLes worktrees s'accumulent : git worktree list en fin de session.

💸 Erreurs de budget

❌ Piège✅ Parade
Lancer dix agents « pour voir »Chaque agent consomme quotas ou crédits ; commencez par deux ou trois tâches bien découpées.
Laisser un agent réessayer en boucleArrêter, corriger la spec, relancer. Une boucle coûte sans produire.

Sources (consultées le 8 novembre 2026) : Veracode 2025 GenAI Code Security Report, CodeRabbit, State of AI vs Human Code Generation, git-worktree, git-stash.
