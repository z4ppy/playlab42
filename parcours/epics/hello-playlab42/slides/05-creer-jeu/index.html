Créer un jeu

Un jeu sépare les règles (le moteur) de l'affichage (le client). Cette séparation rend les règles testables sans navigateur, et réutilisables avec des bots.

Trois pièces

Moteur

engine.js : règles pures, état sérialisable en JSON, aléa via SeededRandom.

Client

index.html et main.js : interface, clavier ou souris, GameKit pour le portail.

Manifest

game.json : joueurs, type turn-based ou real-time, tags, bots disponibles.

Moteur isomorphe

« Isomorphe » veut dire : le même moteur s'exécute dans le navigateur et dans Node (c'est ce que font les tests Jest). Il n'utilise donc ni DOM, ni réseau, ni fichiers, ni Math.random() ou Date.now(). Aucun serveur de jeu n'est déployé aujourd'hui : la compatibilité Node sert aux tests et prépare l'avenir. 

init(config)                          // état initial depuis une seed
isValidAction(state, action, playerId)
getValidActions(state, playerId)
applyAction(state, action, playerId)  // retourne un nouvel état
getPlayerView(state, playerId)        // ce que le joueur a le droit de voir
isGameOver(state)  getWinners(state)  getCurrentPlayer(state)

Une nouvelle partie reçoit une seed explicite depuis le client : l'horloge appartient à l'interface, pas aux règles. Vérifiez qu'une suite d'actions donne le même résultat après sauvegarde puis restauration JSON, sans muter l'état initial. Les moteurs partagent ces contrats, pas une super-classe imposant leurs règles : ils conservent leurs états JSON propres.

Générer et vérifier

  1. Générez un jeu jouable contre un bot : 
    make scaffold TYPE=game ID=ma-course TITLE="Ma course"
  2. Testez le moteur dans Docker : 
    make npm CMD="test -- --runTestsByPath games/ma-course/engine.test.js"
  3. Régénérez le catalogue (make npm CMD="run build:catalogue"), puis ouvrez le jeu dans l'onglet Jeux.

Le gabarit crée engine.js, main.js, style.css, engine.test.js, game.json et un bot dans bots/. Pour une référence plus riche, lisez games/tictactoe/.

Mini-exercice

Un collègue appelle document.querySelector dans applyAction pour afficher le coup. Quel est le problème ?

Correction

Le moteur dépend alors du DOM : il ne tourne plus dans Node, donc plus de test unitaire ni de replay simple. L'affichage appartient au client, qui lit l'état retourné par applyAction.
