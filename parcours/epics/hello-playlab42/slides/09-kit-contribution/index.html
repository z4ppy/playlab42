Le kit de contribution

Une fois la spec écrite, on ne part pas d'une page blanche : le kit génère un point de départ qui fonctionne déjà, en HTML, CSS et JavaScript ordinaires.

Scaffolder un module

Dans le shell du conteneur Docker, depuis la racine du dépôt :

node scripts/scaffold.js <game|tool|epic> <id-kebab-case> --title "Titre"

Raccourcis : npm run scaffold -- tool mon-outil --title "Mon outil" ou make scaffold TYPE=tool ID=mon-outil TITLE="Mon outil".

TypeDestinationCe qui marche tout de suite
gamegames/<id>/Jeu de pierres contre un bot déterministe, moteur testé
tooltools/<id>/Compteur de mots, local, sans CDN
epicparcours/epics/<id>/Deux slides : explication et question

Règles du générateur

  • Pas d'option --force : un dossier existant est refusé, choisissez un autre identifiant.
  • Identifiant : kebab-case, 1 à 64 caractères. Titre : 1 à 120 caractères.
  • Les gabarits sont dans templates/ (suffixe .tpl) : copie et adaptation, pas de nouveau framework.
  • Le générateur produit des fichiers que vous relisez ; il ne promet pas de génération de code au runtime.

La galerie UI et les helpers

Ouvrez /tools/ui-kit/index.html sur votre serveur local : thèmes, boutons, formulaires, statuts et dialogue natif. Les classes ui-* de lib/components.css sont opt-in et reposent sur lib/theme.css et lib/ui.css. Les éléments HTML natifs et leurs libellés restent la base de l'accessibilité.

Localité : tout près du code

  1. Tests à côté du code : engine.test.js dans le dossier du jeu.
  2. Documentation par JSDoc dans les fichiers, guides dans docs/guides/.
  3. Thème : variables CSS de lib/theme.css, pas de couleurs recopiées.

hello-usine, étape kit

Pour notre outil imaginaire, on lancerait (dans Docker) :

node scripts/scaffold.js tool hello-usine --title "Hello usine"

Puis on remplacerait le compteur par le message, en gardant les libellés et le test de contrat.

Mini-question : que faire si le dossier existe déjà ?

Choisir un nouvel identifiant. Il n'existe aucun moyen d'écraser, c'est voulu.
