🏗️ Comment fonctionne un coding agent

Sous les interfaces très différentes, tous les coding agents reposent sur la même mécanique : un modèle de langage placé dans une boucle, avec des outils pour agir et un contexte soigneusement construit. Comprendre cette mécanique aide à rédiger de meilleures demandes et à diagnostiquer les échecs.

La boucle d'agent

Ce schéma descend du pattern ReAct (Yao et al., 2022), qui entrelace raisonnement et actions. Le programme qui entoure le modèle (le harness) fait une grande partie de la qualité de l'agent : outils proposés, gestion du contexte, permissions, vérifications.

Gérer le contexte : le vrai savoir-faire

Une fenêtre de contexte, même très grande, reste limitée et coûteuse. Et un modèle exploite moins bien une information placée au milieu d'un long contexte (effet lost in the middle, Liu et al., 2023). Les agents de 2026 combinent donc plusieurs mécanismes :

MécanismeRôle
Fichiers d'instructions (AGENTS.md, CLAUDE.md…)Conventions et commandes du projet, chargées à chaque session
Recherche dans le codeLire seulement les fichiers utiles plutôt que tout le dépôt
Agent SkillsDossiers avec un SKILL.md : seuls le nom et la description sont chargés au départ, le reste à la demande (progressive disclosure)
Sous-agentsUne sous-tâche dans un contexte séparé, qui ne renvoie que son résultat
CompactionRésumer l'historique quand la conversation devient trop longue

Les standards qui relient les outils

StandardCe qu'il relieÉtat au 8 novembre 2026
MCP (Model Context Protocol) Agent ↔ outils et données externes (tickets, bases, navigateurs…) Version courante 2026-07-28, devenue sans état ; projet de l'Agentic AI Foundation depuis décembre 2025
AGENTS.md Projet ↔ agent : les conventions Format ouvert, projet fondateur de l'Agentic AI Foundation
Agent Skills Savoir-faire réutilisable ↔ agent Format ouvert né chez Anthropic (octobre 2025), confié à l'Agentic AI Foundation en octobre 2026 ; plus de 70 plateformes l'ont intégré selon Anthropic
ACP (Agent Client Protocol) Éditeur ↔ agent Standardise la communication entre éditeurs de code et agents (par exemple Zed ou Mistral Vibe)

Garder la main : permissions, hooks et bacs à sable

  • Permissions : chaque outil peut être autorisé, interdit ou soumis à confirmation. C'est la première ligne de défense.
  • Hooks : des scripts déclenchés à des moments précis de la boucle (par exemple avant ou après un appel d'outil dans Claude Code) pour bloquer une commande, lancer un formateur ou journaliser.
  • Isolation : worktree, conteneur, bac à sable du système (Codex sous Windows) ou machine virtuelle dans le cloud. Plus l'agent est autonome, plus l'isolation doit être forte.

Plusieurs agents

Les orchestrations multi-agents décrites en 2025 sont devenues des fonctions intégrées : sous-agents parallèles, agents en arrière-plan, équipes d'agents expérimentales. Le parcours Développement parallèle avec agents IA détaille comment les utiliser sans conflits.
