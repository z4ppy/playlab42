Algorithmes classiques

Algorithmes de Tri

La quête de la performance, de O(n²) à O(n log n).

🐢 Les tris "naïfs" en O(n²)

Simples à implémenter mais lents pour de grands volumes. Ils restent utiles pour de tout petits tableaux (< 32 éléments).

Bubble Sort

Fait remonter les bulles. Très lent, sauf si presque trié.

Insertion Sort

Comme trier des cartes en main. Excellent sur petits volumes.

Selection Sort

Cherche le min et le place. Toujours O(n²), instable.

🐇 Les tris efficaces en O(n log n)

La limite théorique des tris par comparaison est $\Omega(n \log n)$. Ces algorithmes l'atteignent grâce à l'approche "Diviser pour régner".

Merge Sort (Tri Fusion)

Stable

Divise le tableau en deux, trie récursivement, puis fusionne.
Avantage : Garantie O(n log n) pire cas. Stable.
Inconvénient : Consomme O(n) mémoire supplémentaire.

Quick Sort (Tri Rapide)

Instable

Choisit un pivot, partitionne (plus petit à gauche, plus grand à droite), répète.
Partition de Hoare vs Lomuto : Hoare (deux pointeurs qui se croisent) est 3x plus rapide que Lomuto (un seul pointeur).
Avantage : Cache-friendly, In-place.
Inconvénient : Pire cas O(n²) (limité par Introsort).

Heap Sort (Tri par Tas)

Instable

Utilise une structure de tas binaire.
Avantage : Pas de mémoire supplémentaire O(1), garantie O(n log n).
Inconvénient : Souvent plus lent que QuickSort en pratique.

📜 Le premier programme de tri

Le Tri Fusion (Merge Sort) n'est pas né d'hier. Il a été inventé par John von Neumann en 1945.

À l'époque, il travaillait sur l'EDVAC (l'un des premiers ordinateurs électroniques). Le programme original a été écrit à l'encre sur 23 pages de code manuscrit. L'idée de diviser un problème en sous-problèmes plus petits était révolutionnaire pour le traitement séquentiel des cartes perforées.

💼 Cas Pratiques

Commerce (E-commerce)

"Trier par Prix : Croissant".

Souvent géré par la base de données (ORDER BY), mais le rendu frontend (React/Vue) peut re-trier de petites listes avec le Timsort (natif JS V8).

Jeux Vidéo (Rendu 3D)

Pour gérer la transparence, il faut afficher les objets du plus loin au plus proche (Algorithme du Peintre).

Utilise souvent Radix Sort ou un tri spatial (BSP Tree) car la précision parfaite n'est pas toujours requise à chaque frame.

🤖 Les hybrides modernes (utilisés en Prod)

Timsort (Python, Java, Android)

Merge Sort + Insertion Sort

Inventé par Tim Peters pour Python (2002).

  • Exploite les runs (séquences déjà triées) naturels.
  • Bascule sur Insertion Sort pour les petits blocs (taille 32-64).
  • Complexité : Meilleur cas O(n) sur données réelles !

Introsort (C++ std::sort, .NET)

Quick Sort + Heap Sort

Inventé par David Musser (1997).

  • Démarre en Quick Sort (rapide).
  • Si la profondeur de récursion dépasse $2 \log n$, bascule sur Heap Sort pour éviter le pire cas O(n²).
  • Combine vitesse moyenne et garantie pire cas.
