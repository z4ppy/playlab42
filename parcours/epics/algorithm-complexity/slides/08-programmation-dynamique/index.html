Optimisation

Programmation Dynamique

Transformer des problèmes exponentiels en solutions polynomiales en ne résolvant jamais deux fois la même chose.

🥸 Une origine politique et mathématique

Le terme "Programmation Dynamique" a été choisi par Richard Bellman dans les années 50 pour masquer ses activités mathématiques à Charles Wilson, Secrétaire à la Défense qui détestait la "recherche".

Bellman a choisi "Programmation" (planification militaire) et "Dynamique" (connotation positive en physique) pour sécuriser ses financements.

L'équation de Bellman

Elle exprime la valeur d'un problème de décision en fonction des choix initiaux et de la valeur des problèmes résiduels :

$$V_{i-1}(y) = \max_a \left[ \text{gain}(a, i-1) + V_i(\text{nouvel\_état}(y, a)) \right]$$

Fondement de l'apprentissage par renforcement moderne (Reinforcement Learning).

🧠 Les 2 Piliers

1. Sous-structure Optimale

La solution optimale d'un problème contient les solutions optimales de ses sous-problèmes.

ShortestPath(A->C) =
ShortestPath(A->B) + ShortestPath(B->C)

2. Chevauchement

"Ceux qui ne peuvent se souvenir du passé sont condamnés à le répéter." — George Santayana

Les mêmes sous-problèmes reviennent encore et encore (ex: Fib(3) est calculé partout). La DP les stocke pour ne pas les recalculer.

Fib(5) -> Fib(4) + Fib(3)
Fib(4) -> Fib(3) + Fib(2)

🛠️ Mémoïsation vs Tabulation

Top-Down (Mémoïsation)

  • Direction : Descendante (du problème global vers les cas de base).
  • Évaluation : Paresseuse (calcule uniquement les états requis).
  • Risque : Débordement de pile (Stack Overflow) sur les récursions profondes.
  • Usage : Idéal quand l'espace d'états est vaste mais épars.
# Python
memo = {}
def fib(n):
  if n in memo: return memo[n]
  memo[n] = fib(n-1) + fib(n-2)
  return memo[n]

Bottom-Up (Tabulation)

  • Direction : Ascendante (des cas de base vers le problème global).
  • Évaluation : Avide (calcule tous les sous-problèmes).
  • Optimisation : Permet souvent de réduire l'espace mémoire (ex: O(1) pour Fib).
  • Performance : Meilleure localité de cache, pas d'overhead récursif.
# Python
dp = [0]*(n+1)
dp[1] = 1
for i in range(2, n+1):
  dp[i] = dp[i-1] + dp[i-2]
return dp[n]

📚 Grands Classiques

Sac à Dos (0/1 Knapsack)

O(n ⋅ W)

Pour chaque objet $i$, deux choix : le prendre ou le laisser.
Pseudo-polynomial : Rapide si $W$ est petit, mais exponentiel en fonction du nombre de bits de $W$.

$$dp[i][w] = \max(dp[i-1][w], \; dp[i-1][w-w[i]] + v[i])$$
Preuve d'optimalité (Cut & Paste) : Si une solution optimale contient l'objet $n$, le reste des objets doit être une solution optimale pour la capacité $W - w_n$. Sinon, on pourrait améliorer ce reste et obtenir une meilleure solution globale (contradiction).

Distance de Levenshtein (Wagner-Fischer)

O(n ⋅ m)

Minimum d'opérations (insert, delete, subst) pour transformer $A$ en $B$.

$$dp[i][j] = \begin{cases} dp[i-1][j-1] & \text{si } A[i] = B[j] \\ 1 + \min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1]) & \text{sinon} \end{cases}$$
  • $d[i-1][j]$ : Suppression
  • $d[i][j-1]$ : Insertion
  • $d[i-1][j-1]$ : Substitution

Optimisation espace : O(min(n,m)) possible (Hirschberg).

LIS (Longest Increasing Subsequence)

O(n log n)

Trouver la plus longue sous-suite croissante.

Approche Quadratique $O(n^2)$ :
$$d[i] = 1 + \max(\{d[j] \mid j < i, A[j] < A[i]\} \cup \{0\})$$
Optimisation $O(n \log n)$ : Maintenir un tableau `tail` où `tail[k]` est la plus petite valeur terminale d'une LIS de longueur `k+1`.

Ce tableau reste trié, permettant une Recherche Binaire.
Lien direct avec le "Tri par Patience" (Patience Sorting).

🚀 Techniques Avancées

Bitmask DP

Utilisé pour représenter des sous-ensembles quand $n$ est petit ($n \le 20$). Ex: Voyageur de Commerce (TSP).

state = (mask, last_city)
mask possède le i-ème bit à 1 si ville i visitée.

Interval DP

Pour des problèmes de découpage ou fusion (ex: Multiplication de matrices).

dp[i][j] dépend de dp[i][k] et dp[k+1][j]
Complexité typique : $O(n^3)$

🧪 Laboratoire : Le Sac à Dos

Visualisons le remplissage de la table DP (Tabulation). Pour chaque objet et chaque capacité $w$, on décide : est-ce mieux de prendre l'objet (valeur + meilleur score avec place restante) ou de le laisser (recopie du score précédent)?

💼 Cas Pratiques (Vraie Vie)

1. git diff

L'algorithme de diff (Myers ou LCS) utilise la DP pour trouver la plus longue séquence commune de lignes entre deux fichiers.

+ added line
- removed line

2. Mise en page (Word/LaTeX)

L'algorithme de césure (Knuth-Plass) minimise la "laideur" globale des paragraphes via DP, plutôt que ligne par ligne (Glouton).

3. Base de Données (Join Order)

Les optimiseurs SQL (Postgres) utilisent la DP pour trouver l'ordre de jointures le moins coûteux parmi tous les arbres possibles.
