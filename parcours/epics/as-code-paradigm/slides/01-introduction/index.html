Décrire plutôt qu'agir

Il est des révolutions qui se font dans le fracas, et d'autres qui se propagent dans le silence des terminaux. La transformation « as-code » appartient à la seconde catégorie : plutôt que d'enchaîner des gestes manuels sur des serveurs, on décrit l'état voulu d'un système dans des fichiers texte, et des outils se chargent de l'atteindre.

Cette approche, dont l'Infrastructure as Code est la forme la plus connue, s'est étendue à la configuration, aux politiques de sécurité, à la documentation et aux catalogues. Partout, la même idée : ce qui est écrit peut être versionné, relu, testé et rejoué.

  1. Fichier YAML ou HCL
  2. Commit Git
  3. Revue et pipeline CI/CD
  4. Système mis à jour

En pratique. Au lieu de cliquer dans une console pour créer un serveur, vous écrivez un fichier qui le décrit. Ce fichier est versionné avec Git, relu en équipe dans une pull request, puis appliqué automatiquement.

L'essentiel en 30 secondes

  • As-code : décrire l'infrastructure ou la configuration dans des fichiers versionnés.
  • Outils phares : Terraform ou OpenTofu, Ansible, Kubernetes, Argo CD et Flux.
  • Bénéfices : traçabilité, reproductibilité, collaboration par revue de code.
  • Coûts : courbe d'apprentissage, outillage à maintenir, discipline d'équipe.
  • Le Catalog-as-Code applique les mêmes principes aux inventaires.
